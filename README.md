# EVERSTAR — Memories Beyond Time

EVERSTAR is a private memory journal and time-capsule app. Memory contents are encrypted on the server with AES-256-GCM and remain sealed until the chosen opening time.

## Current architecture

- React 19 + Vite frontend.
- Supabase Auth with persistent PKCE sessions.
- Supabase Postgres stores metadata and encrypted memory payloads.
- `memory-api` authenticates each request, encrypts/decrypts content, enforces ownership and checks the unlock timestamp on the server.
- `media-api` issues one-time upload tokens and short-lived download URLs for the private `memory-attachments` bucket.
- `memory_attachments` stores metadata only; attachment objects remain private.
- A `pg_cron` job creates one in-app notification per capsule when its unlock time arrives.
- Browser clients can read only their own encrypted memory rows and notifications; direct memory writes are not granted to browser roles.

### Required frontend configuration

Copy `.env.example` to `.env` and set the project's publishable key:

```env
VITE_SUPABASE_URL=https://cehddtgitnrquvsaoztx.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=your_publishable_key
```

The URL and publishable key are browser configuration. Never use a Supabase service-role key in the frontend.

### Required Edge Function secrets

In Supabase Dashboard → Edge Functions → Secrets, verify:

- `ENCRYPTION_KEY`: Base64 for exactly 32 cryptographically random bytes.
- `APP_ALLOWED_ORIGINS`: comma-separated exact origins, including the development origin and the deployed website origin.

Do not rename `ENCRYPTION_KEY` to `MEMORY_ENCRYPTION_KEY`; the deployed `memory-api` reads `ENCRYPTION_KEY`. Keep a secure offline backup of the key. Losing it makes encrypted memories unrecoverable.

Supabase supplies the project URL and function service configuration to deployed functions. Never copy service-role credentials into the repository.

### Auth URL settings

In Supabase Authentication → URL Configuration:

- Set the Site URL to the final website origin.
- Add the local development origin and the deployed website origin to Redirect URLs.
- Configure a trusted SMTP provider before inviting real users. The built-in email sender is limited and may not reliably deliver confirmation and recovery emails.

## Database migrations

The files in `supabase/migrations/` are aligned with the current project migration versions. Do not rerun them manually in the already-provisioned project. For a fresh project, apply them in filename order and verify the resulting RLS policies and cron job before accepting real memories.

```

npm test

```

## Notification status

- In-app notifications are generated by the scheduled database job and appear in the app while the user is signed in.
- External browser push notifications are **not yet activated**. They require VAPID public/private keys, a service worker subscription flow, and a scheduled push dispatcher. Do not treat in-app notifications as proof that browser push is configured.

## Production readiness

The repository and Edge Functions are connected to the new Supabase schema, but a real signup, email confirmation, capsule creation/unlock, attachment upload/download, and browser push test must still be completed in a real browser with a test account. Do not enter irreplaceable personal memories until those end-to-end checks pass.
